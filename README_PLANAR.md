## 실행

```bash
cd /home/cvr/GH/MASt3R-PlanarSLAM
./run_d457.sh
```

기존 MASt3R의 OpenGL/ImGui 시각화 프로그램에서 RGB 영상, 컬러 점군, 키프레임 카메라 위치와 연결을 표시합니다. 창 제목은 `MASt3R-PlanarSLAM`입니다. ROS 2 브리지 없이 USB 카메라를 직접 사용합니다. 다른 카메라 프로그램은 종료한 뒤 실행하세요.

```bash
./run_d457.sh --list-devices       # 연결 장치/시리얼 확인
./run_d457.sh --check-camera       # 모델 없이 RGB-D 30프레임 점검
./run_d457.sh --serial 223322300039
./run_d457.sh --no-viz --max-frames 30
./run_d457.sh --disable-planes     # 동일 RGB-D 입력에서 평면 제약만 끄기
./run_d457.sh --sensor-only        # 모델 깊이 보완을 끄고 실측 기반으로 사용
./run_d457.sh --disable-plane-depth # 깊이 평탄화만 끄기 (평면 자세 제약은 유지)
./run_d457.sh --image-size 640      # 기본값: 실제 추론/깊이/저장 640×480
./run_d457.sh --image-size 512      # 기존 512×384 처리로 비교
```

연결된 장치는 SDK에서 `RealSense D455`, serial `223322300039`로 열거됐습니다. 사용자가 연결한 D457을 이 USB 장치로 테스트했습니다. 스트림은 RGB/depth 640×480, 30Hz이며 **현재 기본 추론·깊이·저장 해상도도 640×480**입니다. `dataset.image_size: 640`을 사용하며 `--image-size 512`로 기존 512×384 경로를 선택합니다. 렌즈 보정과 RGB/depth 정렬을 유지하고 처리 해상도에 맞는 `K_frame`을 생성합니다. 세션 중간에 해상도를 변경하거나 서로 다른 해상도의 키프레임을 섞지 않습니다. 원본 MASt3R 실행기 `main.py`와 다른 데이터셋의 기본값은 변경하지 않았습니다. `--fps 5`가 기본 처리 상한입니다. 카메라 30Hz와 실제 추론 처리율은 다르며, 추론이 끝나면 최신 수신 프레임을 처리합니다.

## 640 해상도 검증과 다음 개선안

2026-10-13 검증 기록은 `reports/resolution_640_20261013/`에 있습니다. 현재 체크포인트의 [공식 학습 해상도](https://github.com/naver/mast3r#checkpoints)는 가로 512입니다. 640은 동일 가중치의 추론 해상도 확장이며, 재학습이나 정확도 향상 검증을 의미하지 않습니다.

동일한 실제 RGB-D 12장을 RAM에 받아 512/640으로 순서대로 재생했습니다. 두 경우 모두 초기화 1회와 추적 11회 성공, 키프레임 1개·비키프레임 11개 저장 및 재로딩을 확인했습니다. 화면은 끄고 CUDA 단계 동기화를 사용했으며 초기 3프레임을 시간 통계에서 제외했습니다. 짧은 단일 구간·각 1회 비교이고 장거리 정확도 또는 지속 FPS 시험은 아닙니다.

| 처리 크기 | 처리 시간 중앙값 | 모델 추론 중앙값 | PyTorch 최대 allocated 메모리 |
| --- | ---: | ---: | ---: |
| 512×384 | 231ms | 119ms | 3,158MiB |
| 640×480 | 305ms | 193ms | 3,423MiB |

640에서 픽셀/저장 점 배열은 196,608→307,200, 인코더 토큰은 768→1,200으로 증가합니다. 실제 저장·표시 유효 점은 깊이와 신뢰도에 따라 이보다 적습니다. 위 메모리는 전체 VRAM 점유량이 아닙니다. 기존 저장 맵은 변환하거나 확대하지 않습니다.

추가 실사에서는 기존 OpenGL 뷰어를 켜고 새 키프레임을 매번 요구하는 검증 설정으로 12프레임을 처리했습니다. 12키프레임, 최근 8개+과거 후보 1개 상주, 시각/평면 백엔드와 과거 후보 검증, 640×480 깊이·307,200행 점군 저장 및 정상 GUI 종료를 확인했습니다. 강제 키프레임 설정은 일반 실행보다 느리므로 성능 비교에 쓰지 않습니다. 검증 영상은 RAM에서만 유지했고 임시 맵은 시험 후 제거했습니다. 단위 테스트 65개 통과(512/640 RGB·깊이·K·재투영 일치와 잘못된 크기 거부 포함).

아래는 해상도 확장 당시의 개선 구상입니다. **1번의 일반 표면 보정과 2번의 전역 자세 그래프는 아래 '추가 오차 보정'에 설명한 제한된 형태로 적용했습니다.** 3~5번의 추가 연산 최적화는 구상 단계입니다. 기존 실측 우선 융합·큰 평면 보정·시간 누적 평면 보정·SDPA·대응점 자동 선별·8키프레임 캐시는 유지합니다.

1. **표면 오차:** 기존 평면 전용 시간 보정을 일반 표면의 재투영 일치 검사로 확장합니다. 최근 2~3개 프레임의 실측을 현재 시점에 투영하고, 가림·경계·자세 신뢰도를 검사해 반복 일치하는 관측만 완만하게 융합합니다. 움직이는 물체와 깊이 불연속은 합치지 않고, 모델 보완값은 실측보다 낮은 가중치를 유지합니다. GPU에서 제한된 표본으로 일치 여부를 검사하고 현재 프레임 전체에 결과를 적용하는 방식을 비교할 수 있습니다. 잘못된 자세로 시간 융합하면 잔상이 늘 수 있어 정지 벽의 깊이 분산과 이동 중 경계 보존을 별도로 평가해야 합니다.
2. **겹친 벽과 장거리 오차:** 현재 최근 구간 보정을 넘어 승인된 루프 연결로 전역 키프레임 자세를 보정하는 별도 그래프를 설계합니다. 재투영/평면 잔차가 감소하고 기존 연결이 보존될 때만 자세를 반영합니다. 저장 점군은 각 키프레임 좌표를 유지하고 최신 자세를 적용하므로, 표면을 무조건 평탄화하는 것보다 정렬 문제를 직접 다룹니다. 현재 저장된 연결 ID만으로 완전한 관측 요인이 복구되지는 않으므로 상대 자세·불확실성 저장도 필요합니다.
3. **가벼운 최적화:** 640 원본 점군은 저장하되 위치 계산용 격자 크기를 16→20픽셀로 시험하면 구역 수가 기존 512 설정과 같아집니다(32×24). 높은 신뢰도·윤곽·근거리/원거리 표본은 유지하고, 전체 대응점의 잔차 검사와 실패 시 전체 점 재시도를 계속 사용합니다. 평면 RANSAC도 일정한 표본 예산을 적용할 수 있습니다. 이번 측정에서 자세 계산은 약 10ms, 특징 대응은 약 15ms이므로 이 단계만 줄여서 큰 FPS 향상을 기대해서는 안 됩니다.
4. **주요 병목인 모델 추론:** 모델 단계가 약 193ms로 가장 큽니다. 이미 저정밀 fused attention을 사용하므로, 다음에는 인코더/디코더 선형 연산의 선택적 혼합 정밀도를 별도 A/B 검증하는 것이 우선입니다. cuRoPE와 기하·자세 계산의 FP32 요구를 지키고 대응률·깊이 보완·재위치추정 변화를 검사해야 합니다. 더 큰 변경으로는 중간 프레임에 RGB-D 기하 추적을 사용하고 실패/가림/이동량 증가 시 즉시 모델 추론으로 복귀하는 방식을 고려할 수 있지만, 이는 추적 알고리즘 변경이므로 아직 기본 경로에 넣지 않습니다.
5. **표시 비용:** 키프레임 원본은 보존하고 표시 점군만 voxel/surfel로 합치는 방법은 화면과 메모리 부담을 줄입니다. 모델 추론 시간을 줄이는 효과와 구분해서 평가해야 하며, 자세가 바뀌면 해당 하위 맵을 다시 융합해야 합니다.

실측 깊이 분산·경계 선명도·루프 정렬 잔차·추적 실패율과 단계별 중앙값/p95 시간을 함께 비교한 뒤 개선안을 채택합니다. 독립적인 참값 없이 잔차 감소만으로 절대 정확도 향상을 주장하지 않습니다.

## 추가 오차 보정 (640 실행 기본 적용)

```bash
./run_d457.sh                         # 새 깊이·전역 자세 보정 켜짐
./run_d457.sh --disable-surface-depth # 일반 표면 시간 보정만 끄기
./run_d457.sh --disable-global-poses  # 새 전역 자세 그래프만 끄기
```

`temporal_surface.py`는 추적 성공 후 최근 3프레임의 **보정 전 실측 깊이**를 현재 관측과 대조합니다. 과거 카메라 시점으로 투영해 2회 이상 깊이 차이 2cm 이내, 역사 표준편차 8mm 이내, RGB 차이 0.08 이내의 관측만 사용합니다. 깊이 불연속·구멍 주변은 제외하고, 모델 대체/보완값을 실측 역사로 재사용하지 않습니다. 가려지거나 움직였다고 의심되는 불일치 영역은 융합하지 않지만, 사람을 의미적으로 검출하여 지도에서 지우는 기능은 아닙니다.

강도는 0.5, 새 보정의 최대 변화는 4mm입니다. 이미 평면 보정이 적용된 픽셀을 다시 보정하지 않아 기존 최대 10mm 보정 한도를 유지합니다. 추적 실패, 자세 갱신, 시간·자세 급변 때 역사를 초기화합니다. 최종 깊이와 `X_canon`·표시 특징점을 함께 갱신하며, 키프레임에는 `surface_depth_delta`, `surface_depth_stats`도 저장합니다. 자세 추정 직후 적용되므로 당장 계산을 마친 해당 프레임 자세를 다시 푸는 것은 아니며, 새 키프레임 기하와 이후 추적·맵에 반영됩니다.

`pose_graph.py`는 기존 MASt3R의 승인된 프레임 대응에서 최대 2,048개의 **실측 대 실측** 대응을 추려 RANSAC Sim3 상대 변환을 구합니다. 최소 100점, 인라이어 60%, 4cm 거리 문턱과 RMSE 2cm 이하를 요구합니다. 이것은 연결 수용 문턱이며 최종 지도 오차가 2cm 이내라는 보장이 아닙니다. 상대 변환·표본 수·잔차는 `events.jsonl`의 `global_constraint`에 남습니다. 기존 연결을 단순히 현재 자세에서 역산하여 측정값으로 쓰지 않습니다.

검증된 루프/재위치추정 연결이 추가되면 별도 CPU 스레드에서 최대 1,500개 키프레임의 희소 자세 그래프를 최적화합니다. 연결 요소마다 기준 자세를 고정하고 Huber 손실을 사용합니다. 비용 감소, 기존 일관된 연결 유지, 최대 이동 0.5m·회전 10도·로그 스케일 변화 0.05의 보수적 수용 조건을 적용합니다. 가중치는 경험적 설정이며 보정된 센서 공분산이 아닙니다. 2초보다 자주 새 작업을 시작하지 않고 작업은 한 개만 유지합니다. 1,500개를 넘으면 이 추가 전역 보정은 멈추고 기존 로컬 SLAM은 계속합니다.

비동기 계산 중 키프레임 수나 로컬 자세가 변경되면 결과를 폐기하고 최신 상태로 다시 요청합니다. 따라서 키프레임이 매우 자주 추가되는 구간에서는 전역 보정 적용이 늦어질 수 있습니다. 종료 시 계산을 기다리더라도 마지막 저장 이후의 결과를 반영하지 않습니다. 지도 전체의 점군/모델을 GPU에 다시 올리는 기능이나 완전한 번들 조정은 아닙니다. 실측 대응이 부족한 연결은 새 전역 그래프에서 제외되므로 일부 구간은 연결되지 않을 수 있습니다.

전역 자세가 승인되면 퇴출된 키프레임의 CPU 자세 표까지 갱신합니다. 실시간 과거 요약도 기준 키프레임과 로컬 점을 보존해 다시 배치하고, 디스크 맵은 `map/poses.json`을 통해 최신 자세를 사용합니다. 비키프레임은 기존처럼 기준 키프레임에 따라 움직입니다. 과거에 저장한 세션을 자동으로 다시 처리하지 않으며 **새 실행부터 적용**합니다.

표시는 카메라 좌표의 점을 현재 최적화된 자세로 세계 좌표에 변환하며, 맵 기하나 최적화 계산을 변경하지 않습니다. 적용하려면 실행 중인 프로그램을 종료한 뒤 `./run_d457.sh`로 다시 실행합니다.

## 추가한 알고리즘

[PlanarSLAM](https://github.com/yanyan-li/PlanarSLAM)의 평면을 이용한 구조 제약 아이디어를 MASt3R에 독립적으로 구현했습니다. 원 논문의 전체 point-line-plane/Manhattan SLAM 재현은 아닙니다. 선 특징, Manhattan 방향 추정, 원본 PlanarSLAM 코드의 전체 최적화기는 포함하지 않습니다.

1. RealSense 깊이를 RGB에 정렬하고, SDK의 카메라 모델로 RGB와 깊이를 함께 렌즈 보정합니다. 원본 SDK의 `rs2_project_point_to_pixel`을 사용하므로 inverse Brown 모델도 처리합니다. 깊이는 센서 단위를 미터로 변환하고 0.25~5m 범위 밖과 깊이 누락을 제외합니다.
2. MASt3R는 영상 특징·픽셀 대응·예측 깊이를 계산합니다. 깊이 융합 단계에서는 정상 실측을 유지하고, 실측 이상치와 누락 영역에는 아래의 조건으로 모델 깊이를 대체합니다. 그 뒤 큰 실측 평면 내부에 한해 작은 깊이 노이즈를 보정합니다.
3. 보완된 깊이 점군에서 신뢰도 가중 RANSAC과 SVD로 최대 8개 평면을 추출하고, 아래 큰 평면 기준을 만족하는 실측 영역의 깊이를 제한적으로 보정합니다. 평면은 단위 법선 `n`, 거리 계수 `d`, 지지점 중심과 가중 비율로 표현하며 `n·X + d = 0`입니다.
4. 현재 상대 자세로 변환한 평면을 법선 각도·거리·중심 거리로 검증해 일대일 대응시킵니다. 부호가 반대인 동일 평면도 처리합니다.
5. 추적 Gauss–Newton 계산에 평면 법선/거리 잔차와 해석적 Sim(3) Jacobian을 추가합니다. Huber 가중치와 센서의 미터 스케일 사전 제약을 적용합니다.
6. 기존 CUDA 시각 그래프 최적화 뒤, 시각 대응으로 승인된 키프레임 연결에 한해 평면 그래프 보정을 추가합니다. 첫 노드를 고정하고 시각 자세 사전 제약과 작은 보정량 제한으로 관측 불가능한 방향의 움직임을 억제합니다. CUDA Hessian에 직접 평면을 결합한 완전한 공동 최적화는 아닙니다.

좌표는 RealSense optical 기준 x 오른쪽, y 아래쪽, z 앞쪽입니다. 한 개 평면만으로 평면 접선 방향 이동과 법선 주위 회전을 결정할 수는 없습니다. 시각 대응이 너무 부족하면 평면만으로 추적 성공을 선언하지 않고 기존 재위치추정을 사용합니다.

기대 효과는 평면이 충분한 환경에서 회전·평면 수직 방향 이동의 추가 제약과 실제 깊이에 기반한 크기 유지입니다. 정답 궤적에 대한 정확도 개선, 장거리 드리프트 감소, 움직이는 환경의 성능은 아직 측정하지 않았습니다.

## 실측 우선 깊이 보완

기본 실행에서 `depth_fusion.enabled: true`입니다. 추가 모델 추론 없이, 추적 과정에서 이미 계산하는 MASt3R 자체 카메라 좌표의 Z와 3D confidence를 사용합니다. INIT/재위치추정에서도 해당 프레임의 예측을 사용합니다.

- **실측 정상:** 값을 변경하지 않습니다. 예측과 다르다는 이유만으로 평균내거나 덮어쓰지 않습니다.
- **실측 이상치:** 5×5 주변 실측 중앙값에서 크게 벗어나고, 충분히 높은 confidence의 모델이 그 주변 깊이와 일치하며 실측과는 불일치할 때 모델 값으로 대체합니다. 모델을 실측에 스케일 정렬하지 못하면 실측 대체는 하지 않습니다.
- **실측 누락:** 신뢰도와 범위 조건을 통과한 모델 깊이로 채웁니다. 모델도 비정상/저신뢰도/범위 밖이면 빈 상태로 남깁니다.
- **깊이 전체 누락:** 모델의 metric 예측을 더 높은 confidence 문턱과 낮은 가중치로 사용합니다. 센서 깊이 1% 미만이라는 이유만으로 종료하지 않습니다. 단, RGB 수신 자체가 끊기거나 두 출처 모두 유효하지 않으면 맵을 정상 생성한다고 간주하지 않습니다.

실측과 모델이 동시에 유효한 점 중 실측 이상치를 제외하고 로그 깊이 비율의 중앙값으로 모델 스케일을 보정합니다. 기본적으로 200개 이상, 스케일 0.5~2.0, 로그 잔차 0.15 이내 비율 50% 이상이어야 적용합니다. 센서 기준점이 없으면 이전 프레임의 스케일을 무조건 재사용하지 않고 metric 모델 출력에 의존합니다.

최종 깊이를 카메라 내부 파라미터로 역투영한 **하나의 3D 점군**이 추적·키프레임 CUDA 그래프·재위치추정·평면 추출·화면에 공통으로 전달됩니다. 각 프레임의 보완 결과는 고정하여, 나중에 모델로 채운 점을 실측으로 오인하거나 다른 시점의 예측으로 반복 덮어쓰지 않습니다. MASt3R 내부의 특징 대응 계산은 기존 신경망 출력을 사용합니다.

신뢰도는 확률이 아닌 최적화 가중치입니다. 정상 실측 3.0, 의심 실측 1.8, 모델 보완 1.6~2.0, 무효 0입니다. 추적과 CUDA 그래프에서는 대응 양쪽의 낮은 신뢰도를 반영하며, 영상 대응 confidence 문턱은 별도로 유지합니다. 평면 추출과 평면 제약도 가중 지지점을 사용합니다. 기본 뷰어 문턱 1.5에서는 모델로 채운 점도 보입니다.

프레임에는 `depth_source`로 0=무효, 1=실측, 2=실측 대체, 3=누락 보완을 보관합니다. 콘솔에는 `sensor`, `replaced`, `filled`, `invalid`, `model_scale`, `aligned`를 출력합니다. 이 출처 정보도 키프레임 아카이브에 함께 보관합니다.

설정은 `config/d457_planar.yaml`의 `depth_fusion`에서 조정합니다. 기본 모델 깊이 범위는 0.25~8m입니다. 실측 자체의 처리 범위 0.25~5m를 벗어난 영역도 모델 보완 대상이 될 수 있으며, 이것이 원거리 측정 정확도를 보장하지는 않습니다. 실측의 넓은 영역에 걸친 체계적 오차나 얇은 구조를 모든 경우에 구분할 수는 없습니다. 큰 실측 평면에는 아래의 짧은 시간축 보정을 추가했으며, 모델 깊이에 대한 다중 시점 검증과 confidence 오차 보정 학습은 구현하지 않았습니다.

## 큰 평면의 깊이 노이즈 보정

기본 실행에서 `plane_depth.enabled: true`입니다. 깊이 융합 후 검출된 평면을 후보로 삼고, 신뢰도가 높은 **실측** 지지점만 사용해 다시 적합합니다. 이 단계는 매 프레임 공간적인 깊이 흔들림을 줄입니다. D457 실행기에서는 추적 성공 후 아래의 시간축 보정이 이어집니다. 센서의 절대 거리 교정 기능은 아닙니다.

기본 적용 조건은 다음을 모두 만족하는 연결 영역입니다.

- 실측 지지 영역의 추정 표면적 0.25㎡ 이상, 화면의 10% 이상, 최소 2,500픽셀. 512×384 영상에서는 화면 비율 조건에 따라 약 19,661픽셀 이상이 필요합니다. 떨어진 작은 조각의 면적을 합치지 않습니다.
- 평면 위 두 방향의 지지 범위가 각각 0.35m 이상. 좁고 긴 띠는 제외합니다. 평면 적합은 최대 4,096개의 실측 표본을 사용합니다.
- 적합 잔차 RMS 1㎝ 이하, 평면과의 깊이 차이 3㎝ 이내. 비스듬하게 보이는 면, 깊이 경계 주변 3픽셀 이상, 구멍 주변을 제외합니다.
- 모델로 채우거나 대체한 깊이와 신뢰도가 낮은 실측은 보정하지 않습니다. 주변 깊이와 1.5㎝ 이상 다른 점, 주변 중앙값이 평면과 1㎝ 이상 차이나는 영역도 제외하여 얇거나 조금 돌출된 물체를 보호합니다.

통과한 내부 픽셀은 카메라 시선과 평면의 교차 깊이를 구하고, **오차의 60%를 반영**합니다. 1㎜ 이내 차이는 유지하고, 한 프레임에서의 변경량은 최대 1㎝입니다. 이전 프레임의 보정값을 누적하지 않고 각 프레임에 한 번만 적용합니다. 이 때문에 실제 카메라 이동을 시간 평균으로 지우거나 잔상을 만드는 처리는 하지 않습니다.

- `manifest.json`에는 정상 종료 시 최종 자세/내부 파라미터를 기록합니다. `events.jsonl`에는 실행 중 자세 변경과 연결을 기록합니다. 재로딩할 때는 오래된 키프레임 파일에 박힌 자세 대신 최신 메모리 자세를 사용합니다. 프로세스 재시작 후 검색 인덱스를 복구해 SLAM을 이어가는 기능은 아직 없습니다.

메모리 상주 상세 프레임과 조밀한 최적화 문제는 제한되지만, CPU의 검색 인덱스·자세 목록 및 디스크 사용량은 경로 길이에 따라 증가합니다. 추가 전역 자세 그래프는 검증된 실측 연결을 이용해 과거 자세까지 보정하지만, 전체 조밀한 번들 조정이나 주변화 사전 정보의 보존은 아닙니다. 연결 부족·작업 수용 조건·노드 한도로 과거 보정이 제한될 수 있으며, 경계 불연속이나 장거리 휨을 완전히 해결한다고 보장하지 않습니다.

기본 실행은 72개 attention 층에 PyTorch SDPA를 사용합니다. GPU에서 attention의 Q/K/V에 BF16(지원되지 않으면 FP16)을 사용하고 나머지 모델 가중치와 cuRoPE는 FP32로 유지합니다. `--no-sdpa`로 해제할 수 있지만 메모리 사용이 커집니다. CPU FP32 attention 동등성은 테스트했으며 GPU 저정밀 계산은 원본과 비트 단위로 같지 않습니다.

실행 스크립트는 `/home/cvr/miniconda3/envs/mast3r-slam/bin/python`을 사용합니다. 이 컴퓨터에서는 `pip install -e .`를 다시 실행할 필요가 없습니다. 다른 PC로 옮기면 Python/PyTorch/CUDA 버전과 컴파일된 확장을 해당 환경에 맞춰 준비해야 합니다.

## 저장 맵의 Gaussian 외관 후처리 시험

`offline_appearance.py`는 저장된 RGB·융합 깊이·내부 파라미터와 `map/poses.json`의 최신 자세로 별도의 Gaussian 지도를 만듭니다. 실시간 추적과 원본 점군에는 적용하지 않습니다. Sim3 자세의 스케일을 깊이에 반영한 뒤 SE3 카메라로 변환합니다. 키프레임 8장마다 1장은 외관 평가용으로 제외하고, 나머지 프레임만 초기 점군과 학습에 사용합니다. 평가 자세는 전체 SLAM 결과를 사용하므로 독립적인 위치 정확도 평가가 아닙니다.

```bash
./offline_appearance.sh train maps/20261013_161909_477208 \
  --output postprocessed/my_new_gaussian_test --steps 1800
./offline_appearance.sh view postprocessed/20261013_161909_gaussian_test
```

브라우저에서 `http://127.0.0.1:8090`을 엽니다. `Camera keyframe`을 고르고 `Move to saved camera`를 누르면 저장된 촬영 위치로 이동합니다. 원본 맵은 기존 `./view_saved_map.sh`에서 확인합니다. 후처리 출력 폴더는 새 폴더여야 하며 `gaussians.npz`, 표준 degree-zero Gaussian `gaussians.ply`, 전후 비교 `comparison.jpg`, 평가 기록 `report.json`을 생성합니다. Gaussian PLY는 일반 RGB 점군 PLY와 표현 방식이 다릅니다.

2026-10-13 시험: 새 세션의 키프레임 67장 중 59장 학습/8장 평가, 384×288, Gaussian 18만 개, 1800회 최적화. **평가 RGB PSNR 평균 13.87→18.12dB** (초기 Gaussian 렌더링 대비), 8장 중 7장 개선. 벽면의 거친 무늬, 가까운 물체의 흐림, 움직인 사람의 잔상이 남습니다. 카메라 자세는 고정하고 색·불투명도·크기·방향·최대 축별 3cm 중심 이동만 학습합니다. Gaussian 증식, 전체 자세 최적화, 동적 물체 제거는 포함하지 않는 제한된 후처리 실험이며 Photo-SLAM 재현 구현이 아닙니다. 이 평가 수치는 SLAM FPS나 실측 기하 정확도를 뜻하지 않습니다.

현재 컴퓨터에는 `.venv-map-appearance`에 `gsplat==1.5.3`, `viser==1.1.1`을 설치했습니다. 기존 `mast3r-slam`의 PyTorch를 공유하고 다른 패키지는 이 가상환경에 설치해 기존 환경을 유지합니다. 래퍼의 CUDA 13.2/SM 12.0 설정은 이 PC의 RTX 5060용입니다. GPU 순전파·역전파, Sim3 변환, 출력의 유한값/공분산, PLY 재로딩 및 로컬 뷰어 HTTP 응답을 확인했습니다. 구현 참고: [gsplat rasterization API](https://docs.gsplat.studio/main/apis/rasterization.html).

## 저장 맵의 메시·사진 텍스처 후처리 시험

`offline_textured_mesh.py`는 RTAB-Map의 점군 정리→표면 재구성→사진 텍스처 방식과 유사한 별도 실험입니다. RTAB-Map 자체를 실행하거나 `.db`로 변환한 결과는 아닙니다. Open3D 0.19의 screened Poisson을 사용하고, 깊이·메시 가림 검사를 통과한 사진을 면마다 선택합니다. 노출 보정과 인접 면의 사진 선택 완화를 적용하지만, 전역 자세 재최적화와 AliceVision multiband blending은 포함하지 않습니다.

```bash
./offline_textured_mesh.sh build maps/20261013_161909_477208 \
  --output postprocessed/my_new_mesh_test \
  --voxel .03 --poisson-depth 8 --normal-radius .10 --max-faces 200000
./offline_textured_mesh.sh view postprocessed/20261013_161909_poisson_texture_refined
```

뷰어는 `http://127.0.0.1:8091`입니다. `Display`에서 사진 텍스처, 표면, 정리한 점군을 바꿉니다. `Camera keyframe`과 `Move to saved camera`로 촬영 위치를 선택합니다. `comparison.jpg`는 왼쪽부터 촬영 RGB, 정리한 점군, 회색 메시, 사진 텍스처를 같은 시점에서 비교합니다. 출력에는 `filtered_cloud.ply`, `colored_mesh.ply`, `textured_mesh.obj/.mtl`, `texture_atlas.jpg`, `textured_mesh.glb`, `report.json`이 있습니다. OBJ는 MTL·JPG와 함께 보관합니다.

2026-10-13 실제 저장 맵 67키프레임 시험: 1.5cm voxel/depth 9 설정과 3cm voxel/depth 8/10cm 법선 추정 설정을 비교했습니다. 후자의 `postprocessed/20261013_161909_poisson_texture_refined`는 정리 점군 854,854개, 메시 195,005면, 텍스처 할당 표면적 약 40.8%, CPU 처리 약 30초였습니다. 처리 시간은 설치·뷰어 로딩을 제외하며 실시간 성능 수치가 아닙니다. 텍스처 비율은 생성 메시의 표면적 기준으로, 원본 정보 보존율을 뜻하지 않습니다.

**두 결과 모두 울렁이는 표면, 중복 구조와 회색 미할당 면이 남아 기본 맵 표시로 적용하지 않았습니다.** Poisson은 관측 사이의 빈 공간도 이어 만들 수 있습니다. 비교는 입력 촬영 시점에서 수행했으며 독립적인 정답 대비 정확도 개선을 검증하지 않았습니다. 비키프레임은 이번 재구성에 사용하지 않았고 저장 자세는 고정했습니다. 원본 전체 파일의 처리 전후 SHA-256 일치, OBJ 재로딩·UV 범위·사진 연결·유한 기하값, 합성 평면의 투영·가림·텍스처 방향을 확인했습니다. 라이브 SLAM과 원본 저장 맵은 변경하지 않았습니다.
